CalibraTrack Data Schema
1. Scope
This schema describes the synthetic dataset generated by scripts/generate_data.py.
The reporting period is 2026-01-01 through 2026-12-31. The generator uses seed
20261022 and produces synthetic records only.
2. Entities and relationships
- instrument_types 1-to-many assets
- instrument_types 1-to-many calibration_plans
- calibration_plans 1-to-many assets
- suppliers 1-to-many assets
- assets 1-to-many calibration_events
- assets 1-to-many production_usage
- assets 1-to-many work_orders
- assets 1-to-many emergency_extensions
- assets 1-to-many alerts
- calibration_events 1-to-zero/one certificates (certificates are issued for passing events; one labelled missing-certificate anomaly is intentional)
- calibration_events 1-to-zero/one work_orders (work orders are created for failed events)
- emergency_extensions 1-to-many production_usage through exceptionId when an extension is used
- calibration_events, certificates, work_orders, and emergency_extensions are referenced by audit_records through referenceId and entityType.
3. Entity definitions
instrument_types
Master classification of instruments.
- Primary key: id
- Important attributes: name, measurementUnit, category, status
calibration_plans
Defines the calibration interval and tolerance for an instrument type.
- Primary key: id
- Foreign key: instrumentTypeId -> instrument_types.id
- Important attributes: interval (months), tolerance, toleranceUnit, effectiveFrom, effectiveTo
suppliers
Synthetic supplier master data.
- Primary key: supplierId
- Important attributes: supplierName, supplierCode, country, contactEmail, status
assets
Registered instruments/equipment.
- Primary key: id
- Foreign keys: instrumentTypeId -> instrument_types.id; calibrationPlanId -> calibration_plans.id; supplierId -> suppliers.supplierId
- Important attributes: serialNumber, referenceValue, lastCalibration, interval, dueDate, status
calibration_events
Historical calibration measurements and decisions.
- Primary key: id
- Foreign keys: assetId -> assets.id; calibrationPlanId -> calibration_plans.id
- Important attributes: date, measured, reference, tolerance, error, result, engineer, nextDueDate
- Decision rule: error = round(abs(measured - reference), 3). Result is Pass when error <= tolerance, otherwise Fail.
certificates
Evidence document record for a passed calibration.
- Primary key: id
- Foreign keys: calibrationId -> calibration_events.id; assetId -> assets.id
- Important attributes: issueDate, expiryDate, status, issuedBy, documentReference
work_orders
Corrective maintenance work generated for failed calibration events.
- Primary key: id
- Foreign keys: assetId -> assets.id; calibrationId -> calibration_events.id
- Important attributes: status, impactAssessment, downtimeStart, downtimeEnd, downtimeHours, correctiveAction, technician, verificationStatus
emergency_extensions
Time-bounded approved exception for an instrument.
- Primary key: extensionId
- Foreign key: assetId -> assets.id
- Important attributes: approvedBy, approvalDate, effectiveFrom, effectiveTo, justification, status
production_usage
Records use of an instrument in production.
- Primary key: id
- Foreign keys: assetId -> assets.id; optional exceptionId -> emergency_extensions.extensionId
- Important attributes: usageDate, operator, productionLine, status, issueType, batchId
- Decision rule: use the latest calibration on or before the usage date. A failed latest calibration makes use invalid. A passed calibration is valid through its nextDueDate. Beyond that date, use is valid only during an approved extension window.
alerts
Generated operational alert for an asset.
- Primary key: id
- Foreign key: assetId -> assets.id
- Important attributes: alertType, severity, description, date, status, referenceId
audit_records
Synthetic traceability history.
- Primary key: id
- Polymorphic reference: referenceId plus entityType points to the referenced record.
- Important attributes: activity, description, performedBy, date, previousState, newState
ground_truth
Label file describing intentional anomalies inserted for evaluation.
- Primary key: anomalyId
- entityType and entityId identify the affected record.
- issueType identifies the anomaly category.
- expectedLabel is Anomaly.
4. Intentional anomaly scenarios
Exactly five scenarios are injected and recorded in ground_truth.csv and ground_truth.json:
1. INCORRECT_DUE_DATE: an asset due date is shifted by three days.
2. CERTIFICATE_WRONG_ASSET: a certificate points to a different asset than its calibration event.
3. MISSING_IMPACT_ASSESSMENT: a work order's impact assessment is set to Required.
4. MISSING_CERTIFICATE: a passing calibration event has no certificate.
5. EXPIRED_USE_WITHOUT_EXCEPTION: an invalid production-use record is deliberately changed to Valid without an exception.
These records are intentional test cases, not accidental generator defects. Validation must identify and explicitly exempt only the corresponding labelled records.
5. Storage
Every generated dataset is exported as CSV and JSON. The same datasets are loaded into
calibratrack.sqlite; calibratrack_seed.sql is a SQLite SQL dump. The schema is
represented by the generated columns and relationships described above
